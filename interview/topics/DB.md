# SQL BD

**Реляционная база данных (SQL)** — база, где данные хранятся в формате таблиц, они строго структурированы и связаны друг с другом. В таблице есть строки и столбцы, каждая строка представляет отдельную запись, а столбец — поле с назначенным ей типом данных. В каждой ячейке информация записана по шаблону.

**Преимущества SQL**:
- соответствия требованиям ACID
- целостность данных
- структурированность

**Недостатки SQL:**
- реляционные базы плохо масштабируются, с ними крайне сложно создавать распределенные хранилища
- проектирование крупных баз с множеством компонентов требует значительных усилий. Это приведение сущностей к нормальным формам и сложности в отображении связей типа многие-ко-многим. Такие схемы тяжело читать и понимать их бизнес-применение
- эволюция схемы данных почти всегда отстает от новых потребностей бизнеса. Миграция на обновленную схему занимает много времени, в течение которых сервер недоступен

**Что быстрее SQL или NoSQL:**  
NoSQL — название всех технологий, которые не являются SQL, БД документов, БД ключей-значений, БД событий - все это NoSQL.  
Это разный функционал, все зависит от задач.

**Примеры:**
- Oracle
- MySQL
- SQLServer
- PostgreSQL

**Нормализация** — 
процесс организации данных, цель которого избежать дублирования и избыточности.   

Преимущества:
- Лучшая организация базы данных
- Больше таблиц с небольшими строками
- Эффективный доступ к данным
- Большая гибкость для запросов
- Быстрый поиск информации
- Проще реализовать безопасность данных
- Позволяет легко модифицировать
- Сокращение избыточных и дублирующихся данных
- Более компактная база данных
- Обеспечивает согласованность данных после внесения изменений

**Нормальные формы**

1НФ:
- В каждой клетке таблицы только одно значение
- Не должно быть повторяющихся строк

2НФ:
- 1НФ
- Есть первичный ключ
- Все атрибуты зависят от первичного ключа, а не от какой-то ее части

3НФ:
- 2НФ
- Все атрибуты зависят от первичного ключа, но не от других атрибутов

**ACID:**  

**Атомарность (Atomicity).** Гарантирует, что будут выполнены все операции в транзакции, либо ни одной.  
**Согласованность (Consistency).** Гарантирует, что данные должны соответствовать всем правилам валидации, до и после успешной транзакции.  
**Изолированность (Isolation).** Во время выполнения транзакции, параллельные транзакции не должны оказывать влияние на её результат.  
**Устойчивость (Durability).** Независимо от проблем с оборудованием, изменения, сделанные успешно завершённой транзакцией, должны остаться сохранёнными после возвращения системы в работу.

------------
**Индекс** — 
повышает производительность поиска данных. Индекс формируется из значений одного или нескольких столбцов таблицы и указателей на соответствующие строки таблицы и, таким образом, позволяет искать строки, удовлетворяющие критерию поиска.

- Уникальный индекс (Unique Index): Не позволяет полю иметь повторяющиеся значения, если столбец индексируется уникально. Если первичный ключ определен, уникальный индекс может быть применен автоматически.  
- Кластеризованный индекс (Clustered Index): Строки таблицы упорядочены по значению ключа этого индекса. Каждая таблица может иметь только один кластеризованный индекс.  
- Некластеризованный индекс (Non-Clustered Index): не изменяет физический порядок таблицы и поддерживает логический порядок данных. Каждая таблица может иметь много некластеризованных индексов.


Индексы могут быть реализованы различными структурами. Наиболее часто употребимы B*-деревья, B+-деревья, B-деревья и хеши.

**Проблемы:**  
Большое кол-во индексов замедляет операции добавления, обновления, удаления строк таблицы, поскольку при этом приходится обновлять сами индексы. Кроме того, индексы занимают дополнительный объем памяти.
