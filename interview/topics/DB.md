# SQL BD

**Реляционная база данных (SQL)** — база, где данные хранятся в формате таблиц, они строго структурированы и связаны
друг с другом. В таблице есть строки и столбцы, каждая строка представляет отдельную запись, а столбец — поле с
назначенным ей типом данных. В каждой ячейке информация записана по шаблону.

**Преимущества SQL**:

- соответствия требованиям ACID
- целостность данных
- структурированность

**Недостатки SQL:**

- реляционные базы плохо масштабируются, с ними крайне сложно создавать распределенные хранилища
- проектирование крупных баз с множеством компонентов требует значительных усилий. Это приведение сущностей к нормальным
  формам и сложности в отображении связей типа многие-ко-многим. Такие схемы тяжело читать и понимать их
  бизнес-применение
- эволюция схемы данных почти всегда отстает от новых потребностей бизнеса. Миграция на обновленную схему занимает много
  времени, в течение которых сервер недоступен

**Что быстрее SQL или NoSQL:**  
NoSQL — название всех технологий, которые не являются SQL, БД документов, БД ключей-значений, БД событий.
Это разный функционал, все зависит от задач.

**Примеры:**

- Oracle
- MySQL
- SQLServer
- PostgreSQL

------------
**Нормализация** —
процесс организации данных, цель которого избежать дублирования и избыточности.

Преимущества:

- Лучшая организация базы данных
- Больше таблиц с небольшими строками
- Эффективный доступ к данным
- Большая гибкость для запросов
- Быстрый поиск информации
- Проще реализовать безопасность данных
- Позволяет легко модифицировать
- Сокращение избыточных и дублирующихся данных
- Более компактная база данных
- Обеспечивает согласованность данных после внесения изменений

**Нормальные формы**

1НФ:

- В каждой клетке таблицы только одно значение
- Не должно быть повторяющихся строк

2НФ:

- 1НФ
- Есть первичный ключ
- Все атрибуты зависят от первичного ключа, а не от какой-то ее части

3НФ:

- 2НФ
- Все атрибуты зависят от первичного ключа, но не от других атрибутов

------------
**Денормализация** — повышение производительности, через упрощение доступа к данным или через создание таблиц с
результатами отчетов.

**DIMENSIONAL MODELING** – это метод структуры данных, оптимизированный для хранения данных в хранилище данных. Целью
размерной модели является оптимизация базы данных для быстрого поиска данных.

- Схема Звезда
- Схема Снежинка

# **Транзакции**

**Транзакции** —
Объединение операций, для выполнения всех, либо ни одной.

**Транзакции в SQL**

- BEGIN — создать новую транзакцию
- COMMIT — сохранить изменения в БД
- ROLLBACK — отменить изменения

**Уровни изоляции транзакции** —

| **Уровень**          | **Dirty Read** | **Non-repeatable Read** | **Phantom Read** | Полность изолированы |
|----------------------|----------------|-------------------------|------------------|----------------------|
| **READ UNCOMMITTED** | ✅ Возможны     | ✅ Возможны              | ✅ Возможны       | ❌ Нет                |
| **READ COMMITTED**   | ❌ Нет          | ✅ Возможны              | ✅ Возможны       | ❌ Нет                |
| **REPEATABLE READ**  | ❌ Нет          | ❌ Нет                   | ✅ Возможны       | ❌ Нет                |
| **SERIALIZABLE**     | ❌ Нет          | ❌ Нет                   | ❌ Нет            | ✅ Да                 |

---

📌 **Что они означают?**

- Потерянное обновление — Две параллельные транзакции меняют одни и те же данные. Итоговый результат обновления предсказать невозможно.
- **Грязное чтение**: один поток читает **неподтверждённые** (`ROLLBACK` может отменить их) данные
- **Неповторяемое чтение**: между двумя `SELECT` другой поток **изменил/удалил** строки
- **Фантомное чтение**: между `SELECT` другой поток **добавил** новые строки

**Режимы изоляции** —

- Потерянное обновление — Две параллельные транзакции меняют одни и те же данные. Итоговый результат обновления
  предсказать невозможно.
- «Грязное» чтение — В результатах запроса появляются промежуточные результаты параллельной транзакции, которая ещё не
  завершилась.
- Неповторяющееся чтение — Запрос с одними и теми же условиями даёт неодинаковые результаты в рамках транзакции.
- Фантомное чтение — В результатах повторяющегося запроса появляются и исчезают строки, которые модифицирует
  параллельная транзакция.

Чем выше уровень изоляции, тем большей производительностью вы жертвуете.

**Интерфейс для управления транзакциями** —
Spring предлагает вам интерфейс PlatformTransactionManager / TransactionManager, который по умолчанию поставляется с парой удобных реализаций. Одна из них – DataSourceTransactionManager.

**ACID:**

| **Свойство**                      | **Что значит**                                            | **Как это достигается в SQL?**                     |
|-----------------------------------|-----------------------------------------------------------|----------------------------------------------------|
| **Атомарность (Atomicity)**       | Все изменения успешны либо ни одно не выполняется         | `ROLLBACK` при ошибке                              |
| **Согласованность (Consistency)** | Данные всегда остаются корректными (валидные ключи, типы) | Ограничения (`PRIMARY KEY`, `FOREIGN KEY`)         |
| **Изолированность (Isolation)**   | Транзакции не оказывают влияние друг на друга             | Уровни изоляции (`SERIALIZABLE`, `READ COMMITTED`) |
| **Устойчивость (Durability)**     | Изменения сохраняются даже после сбоя                     | Лог транзакций (`WAL` в PostgreSQL)                |

**Индексы в базах данных** —
значительно улучшают производительность поиска данных. Индекс создается на основе значений одного или нескольких столбцов таблицы и содержит указатели на соответствующие строки, что позволяет быстро находить данные, соответствующие заданным критериям.

- Уникальный индекс (Unique Index): Гарантирует, что значения в индексируемом столбце не будут повторяться. При наличии первичного ключа уникальный индекс может быть создан автоматически.
- Кластеризованный индекс (Clustered Index): Определяет физический порядок строк в таблице на основе значений ключа. Каждая таблица может иметь только один кластеризованный индекс.
- Некластеризованный индекс (Non-Clustered Index): Не изменяет физический порядок строк в таблице, но поддерживает логический порядок данных. Таблица может иметь множество некластеризованных индексов.

Индексы могут быть реализованы с использованием различных структур данных. Наиболее распространены B*-деревья, B+-деревья, B-деревья и хеши.

**Проблемы:**  
Избыточное количество индексов может замедлить операции INSERT, UPDATE и DELETE строк, так как при этом необходимо обновлять сами индексы. Кроме того, индексы требуют дополнительного объема памяти.

**Connection pool** —
Некотором множество, в котором хранятся соединения с базой.
Коннект требует времени и ресурсов. Если под каждый запрос делать подключение к базе, то отклик нашего приложения будет
невероятно низким по скорости.
Когда мы запрашиваем новое соединение, то connection pool его создаёт, а при закрытии он не закрывает его, а сохраняет в
connection pool.
И если мы снова запросим соединение у connection pool, то он даст нам одно из старых вместо того, чтобы создавать новое.
