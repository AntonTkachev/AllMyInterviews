#AWS сервисы

1. Amazon Redshift – аналитическая база данных

Amazon Redshift — это облачное хранилище данных (Data Warehouse), предназначенное для быстрого анализа больших объемов
данных.

🔹 Ключевые особенности:
✔ MPP (Massively Parallel Processing) – обработка запросов параллельно на нескольких узлах.
✔ Колонночное хранилище – быстрее обрабатывает запросы, чем обычные реляционные базы данных.
✔ Поддержка SQL – совместим с PostgreSQL.
✔ Интеграция с S3, Glue, Kinesis, Athena – позволяет загружать и анализировать данные из других AWS-сервисов.

🛠 Когда использовать?
✔ Для анализа больших данных (Big Data).
✔ Когда нужна быстрая агрегация и обработка отчетов.
✔ Для бизнес-аналитики (BI).

2. CloudWatch – мониторинг и логирование

AWS CloudWatch – сервис для мониторинга ресурсов и логирования событий в AWS.

🔹 Ключевые возможности:
✔ Мониторинг метрик (CPU, RAM, дисковая нагрузка).
✔ Алармы (CloudWatch Alarms) – триггеры на метрики (например, CPU > 80%).
✔ Логирование (CloudWatch Logs) – сбор и анализ логов приложений и сервисов.
✔ Автоматические действия – например, запуск Auto Scaling, если нагрузка растет.

🛠 Когда использовать?
✔ Для мониторинга EC2, Lambda, RDS и других AWS-ресурсов.
✔ Для тревожных уведомлений о сбоях или высокой нагрузке.
✔ Для анализа логов приложений.

3. CloudShell – терминал в браузере

AWS CloudShell — это облачная консоль, которая предоставляет терминал в браузере для работы с AWS CLI.

🔹 Ключевые возможности:
✔ Запуск AWS CLI без установки на локальный компьютер.
✔ Предустановленные инструменты (Python, Git, Terraform).
✔ Доступ к IAM-авторизованным ресурсам (например, S3, EC2).

🛠 Когда использовать?
✔ Если нет доступа к локальному AWS CLI.
✔ Для быстрого администрирования AWS.
✔ Для тестирования и отладки команд.

4. AWS Lambda – serverless-функции

AWS Lambda – это serverless платформа для выполнения кода без развертывания серверов.

🔹 Ключевые возможности:
✔ Запуск кода в ответ на события (например, HTTP-запрос, загрузка файла в S3).
✔ Поддержка множества языков (Java, Python, Node.js, Go и др.).
✔ Автоматическое масштабирование – AWS сам увеличивает или уменьшает количество исполняемых функций.
✔ Оплата только за использованные ресурсы.

🛠 Когда использовать?
✔ Автоматическая обработка событий (загрузка файлов, обновление данных).
✔ API-бэкенды для микросервисов.
✔ Автоматизация инфраструктуры.

5. IAM (Identity and Access Management) – управление доступом

AWS IAM – это система управления пользователями, ролями и правами доступа в AWS.

🔹 Ключевые возможности:
✔ Пользователи, группы, роли – управление аккаунтами и разрешениями.
✔ Политики (Policies) – правила доступа, основанные на JSON.
✔ MFA (Многофакторная аутентификация) – дополнительная безопасность.
✔ IAM Roles – временные права доступа для сервисов (например, Lambda может работать с S3).

🛠 Когда использовать?
✔ Для разграничения доступа к ресурсам AWS.
✔ Для безопасности при работе с AWS API.
✔ Для настройки сервисных учетных записей.

6. AWS Health Dashboard – мониторинг работоспособности AWS

AWS Health Dashboard – это панель мониторинга состояния сервисов AWS.

🔹 Ключевые возможности:
✔ Мониторинг инцидентов и простоев в AWS.
✔ Уведомления о проблемах с конкретными регионами.
✔ История работоспособности сервисов (можно посмотреть проблемы в прошлом).

🛠 Когда использовать?
✔ Если сервис AWS работает нестабильно и нужно проверить статус.
✔ Для оповещения об инцидентах и плановых работах.
✔ Для разбора инцидентов и поиска причин сбоев.

7. AWS Secrets Manager – управление секретами

Secrets Manager – сервис для хранения и управления чувствительными данными (пароли, API-ключи, сертификаты).

🔹 Ключевые возможности:
✔ Безопасное хранение секретов (паролей, API-ключей).
✔ Автоматическая ротация паролей (например, обновление пароля в базе данных).
✔ Интеграция с RDS, Lambda, EC2.

🛠 Когда использовать?
✔ Хранение паролей и API-ключей в безопасном виде.
✔ Защита конфиденциальных данных в микросервисах.
✔ Автоматическое обновление секретов без простоя сервисов.

8. Amazon S3 (Simple Storage Service) – облачное хранилище

Amazon S3 – это объектное хранилище, предназначенное для хранения файлов, резервных копий и логов.

🔹 Ключевые возможности:
✔ Объектное хранилище – файлы до 5 ТБ.
✔ Разные классы хранения (Standard, IA, Glacier).
✔ Версионирование – хранение старых версий файлов.
✔ Политики доступа (Bucket Policy, ACL).

🛠 Когда использовать?
✔ Хранение логов, бэкапов, статических файлов.
✔ Интеграция с CloudFront для раздачи контента.
✔ Долговременное хранение архивов и медиафайлов.

9. AWS Certificate Manager (ACM) – управление SSL/TLS сертификатами

AWS ACM – это сервис управления сертификатами, который автоматически выпускает и обновляет SSL/TLS-сертификаты.

🔹 Ключевые возможности:
✔ Бесплатные сертификаты для доменов в AWS.
✔ Автоматическое продление сертификатов.
✔ Интеграция с ALB, CloudFront, API Gateway.

🛠 Когда использовать?
✔ Настройка HTTPS для веб-сайтов и API.
✔ Защита внутреннего трафика в AWS.
✔ Управление сертификатами без ручного обновления.

# Containerization в AWS: ECS vs EKS vs Fargate

AWS предоставляет несколько сервисов для работы с контейнерами. Разберём основные различия между **ECS, EKS и Fargate**.

| Сервис                               | Описание                                                                                                | Когда использовать?                                                             |
|--------------------------------------|---------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------|
| **ECS (Elastic Container Service)**  | Собственный сервис AWS для управления контейнерами. Поддерживает запуск контейнеров на EC2 или Fargate. | Если нужен полностью управляемый сервис для Docker-контейнеров.                 |
| **EKS (Elastic Kubernetes Service)** | Полностью управляемый Kubernetes-кластер в AWS. Позволяет запускать контейнеры в Kubernetes-окружении.  | Если требуется работать с Kubernetes.                                           |
| **Fargate**                          | Serverless-решение для запуска контейнеров без управления серверами. Используется с ECS и EKS.          | Если не хочется управлять инфраструктурой, а нужно просто запускать контейнеры. |

### 🔹 Основные различия:

- **ECS** — проще в настройке, но менее гибкий по сравнению с Kubernetes.
- **EKS** — подходит для Kubernetes-энтузиастов, но сложнее в управлении.
- **Fargate** — убирает необходимость управлять серверами, но дороже.

📌 **Выбор зависит от требований проекта и уровня контроля, который вам нужен.**
