# Java Collections

![Java Collections](../../image/Java_Collections.jpg)

## Основные интерфейсы коллекций

### List
- **ArrayList**: Реализует список на основе массива.
- **LinkedList**: Реализует связанный список.

### Queue
- **PriorityQueue**: Очередь с приоритетами.
- **LinkedList**: Может использоваться как очередь.

### Set
- **HashSet**: Реализует множество на основе хеш-таблицы.
- **LinkedHashSet**: Сохраняет порядок вставки.
- **TreeSet**: Реализует множество на основе красно-черного дерева.

### Map
- **HashMap**: Реализует отображение на основе хеш-таблицы.
- **LinkedHashMap**: Сохраняет порядок вставки.
- **TreeMap**: Реализует отображение на основе красно-черного дерева.

## Реализации коллекций

### Array
- **ArrayList**: Список на основе массива. Быстрый доступ по индексу, но медленные операции вставки/удаления в середине.

### Linked
- **LinkedList**: Связанный список. Быстрые операции вставки/удаления, но медленный доступ по индексу.

### Tree
- **TreeMap** и **TreeSet**: Реализованы на основе красно-черного дерева. Обеспечивают упорядоченное хранение элементов.

## Сравнение реализаций

### ArrayList VS LinkedList
- **ArrayList**:
  - Быстрый доступ по индексу. - почему??
  - Медленные операции вставки/удаления в середине. - почему??
  - Нет дополнительных расходов на хранение связей между элементами.

- **LinkedList**:
  - Быстрые операции вставки/удаления - почему??
  - Медленный доступ по индексу - производятся перебором с начала или конца
  - Дополнительные затраты на хранение связей между элементами.

  
# HashMap
HashMap состоит из bucket`ов, «bucket» — это элементы массива, которые хранят ссылки на списки элементов.
При добавлении новой пары ключ-значение, вычисляет хеш-код ключа, на основании хеш-кода вычисляется номер корзины, в
которую добавится новый элемент.

1. Корзина пустая - в нее сохраняется ссылка на новый элемент.
2. Есть элемент - последовательно переходим по ссылкам между элементами в цепочке, до последнего элемента, от которого и
   ставится ссылка на новый элемент.
3. Если в списке был найден элемент с таким же ключом - он заменяется.

**HashMap** - хранение данных в виде пар ключ/значение, где у ключей есть хэши, то есть числовые уникальные
идентификаторы. Они высчитываются для каждого ключа.

### HashMap VS TreeMap
Сходства:
* Реализуют java.util.Map интерфейс.
* Реализации HashMap, а также TreeMap не синхронизированы, Collections.synchronizedSortedMap() - синхронизированный
  доступ

### HashMap VS TreeMap
- **HashMap**:
  - Использует хеш-таблицу.
  - Порядок итерации не определен.
  - Сложность методов get, put, containsKey, remove — O(1). - почему?
  - Допускает нулевые значения и ключи.
  
- **TreeMap**:
  - Использует красно-черное дерево.
  - Элементы упорядочены.
  - Сложность методов get, put, containsKey, remove — O(log(n)). - почему?
  - Допускает нулевые значения, но не нулевые ключи (если используется естественный порядок).

- HashMap когда производительность критична, а порядок ключей не имеет значения.
- TreeMap когда ключи необходимо упорядочить, используя их естественный порядок или с помощью компаратора.
- LinkedHashMap если порядок вставки ключей должен быть сохранен.
- TreeMap - Бинарный поиск, потому что всегда делим на половину

### Деревья
- **Обычное дерево**: Любое количество наследников.
- **Бинарное дерево**: Два наследника, худшая сложность O(n).
- **Красно-черное дерево**: Не позволяет стать 'списком'.
- **B-дерево**: O(log n), хранит много ключей в одном узле, уменьшает высоту дерева.
