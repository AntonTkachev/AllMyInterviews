# Big O

![Java Collections](../../image/O.png)

## 🔹 **List**

### **1. ArrayList**

**📌 Описание:**

- Динамический массив, который автоматически расширяется при добавлении элементов.
- Индексация позволяет быстро получать элементы.

**📌 Временная сложность операций:**

| Операция           | Сложность       | Почему?                                                                   |
|--------------------|-----------------|---------------------------------------------------------------------------|
| Доступ по индексу  | `O(1)`          | Прямой доступ к элементам через индекс.                                   |
| Вставка в конец    | `O(1)` / `O(n)` | Вставка идёт в конец, но при переполнении массива требуется копирование ( 
 `O(n)`).           |
| Вставка в середину | `O(n)`          | Элементы сдвигаются вправо.                                               |
| Удаление элемента  | `O(n)`          | После удаления элементы сдвигаются влево.                                 |

**📌 Когда использовать?**

- Когда важен **быстрый доступ по индексу** (`O(1)`).
- Когда **вставки и удаления происходят в конце списка**.
- **НЕ подходит**, если требуется **частое удаление и вставка в середину**.

---

### **2. LinkedList**

**📌 Описание:**

- Двусвязный список, где каждый элемент (`Node`) хранит **ссылки на предыдущий и следующий**.
- Быстрая вставка и удаление, но медленный доступ по индексу.

**📌 Временная сложность операций:**

| Операция                    | Сложность | Почему?                                                 |
|-----------------------------|-----------|---------------------------------------------------------|
| Доступ по индексу           | `O(n)`    | Требуется перебор элементов по ссылкам.                 |
| Вставка в начало / середину | `O(1)`    | Изменяются ссылки, нет необходимости сдвигать элементы. |
| Удаление элемента           | `O(1)`    | Аналогично вставке, просто меняются ссылки.             |

**📌 Когда использовать?**

- Когда требуется **частое добавление или удаление элементов**.
- Если **индексированный доступ не критичен**.
- **НЕ подходит**, если нужно **часто получать элементы по индексу** (`O(n)`).

---

## 🔹 **Set**

### **3. HashSet**

**📌 Описание:**

- Хранит **уникальные элементы** без определённого порядка.
- Использует **хеш-таблицу** (`HashMap` под капотом).

**📌 Временная сложность операций:**

| Операция       | Сложность | Почему?                                                    |
|----------------|-----------|------------------------------------------------------------|
| Добавление     | `O(1)`    | Вычисляется **хеш**, сразу помещается в таблицу.           |
| Удаление       | `O(1)`    | Идёт поиск по хешу, затем удаление.                        |
| Поиск элемента | `O(1)`    | Поиск происходит по **хешу**, без перебора всех элементов. |

**📌 Когда использовать?**

- Когда нужно **хранить только уникальные элементы**.
- Когда **не важен порядок вставки**.
- **НЕ подходит**, если требуется **упорядоченное хранение**.

---

### **4. LinkedHashSet**

**📌 Описание:**

- Работает как `HashSet`, но **сохраняет порядок вставки**.

**📌 Временная сложность операций:**

| Операция   | Сложность | Почему?                                                        |
|------------|-----------|----------------------------------------------------------------|
| Добавление | `O(1)`    | Аналогично `HashSet`, но дополнительно ведётся связный список. |
| Удаление   | `O(1)`    | Быстрое удаление по **хешу** и обновление связного списка.     |
| Поиск      | `O(1)`    | Поиск по **хешу**.                                             |

**📌 Когда использовать?**

- Когда **нужны уникальные элементы** + **сохранение порядка**.
- **НЕ подходит**, если **важна эффективность использования памяти** (из-за хранения связей).

---

### **5. TreeSet**

**📌 Описание:**

- Основан на **красно-черном дереве**.
- Все элементы **хранятся в отсортированном порядке**.

**📌 Временная сложность операций:**

| Операция   | Сложность  | Почему?                                         |
|------------|------------|-------------------------------------------------|
| Добавление | `O(log n)` | Выполняется вставка с **балансировкой дерева**. |
| Удаление   | `O(log n)` | Требуется **поиск узла**, затем балансировка.   |
| Поиск      | `O(log n)` | Используется **бинарный поиск** по дереву.      |

**📌 Когда использовать?**

- Когда **нужен автоматический порядок сортировки**.
- Когда требуется **эффективный диапазонный поиск**.
- **НЕ подходит**, если нужен **быстрый доступ `O(1)`**.

---

## 🔹 **Map**

### **6. HashMap**

**📌 Описание:**

- Хранит пары **ключ → значение**.
- Основан на **хеш-таблице**.
- `null` может быть **и в ключе, и в значении**.

**📌 Временная сложность операций:**

| Операция       | Сложность | Почему?                                                    |
|----------------|-----------|------------------------------------------------------------|
| Вставка        | `O(1)`    | Вычисляется **хеш**, элемент сразу записывается.           |
| Поиск по ключу | `O(1)`    | Поиск по **хешу**, не требуется перебор.                   |
| Удаление       | `O(1)`    | Аналогично поиску, только дополнительно удаляется элемент. |

**📌 Когда использовать?**

- Когда требуется **быстрый поиск по ключу** (`O(1)`).
- **НЕ подходит**, если важен **порядок элементов**.

---

### **7. LinkedHashMap**

**📌 Описание:**

- Основан на `HashMap`, но **сохраняет порядок вставки**.

**📌 Временная сложность операций:**

| Операция       | Сложность | Почему?                                                        |
|----------------|-----------|----------------------------------------------------------------|
| Вставка        | `O(1)`    | Аналогично `HashMap`, но дополнительно ведётся связный список. |
| Поиск по ключу | `O(1)`    | Поиск по **хешу**.                                             |
| Удаление       | `O(1)`    | Удаление по **хешу** и обновление связного списка.             |

**📌 Когда использовать?**

- Когда нужен **быстрый поиск `O(1)`**, но с **сохранением порядка**.
- **НЕ подходит**, если память критична, так как требуется **дополнительное хранение ссылок**.

---

## 📌 Итог: Когда использовать какую коллекцию?

| Коллекция         | Когда использовать?                                               |
|-------------------|-------------------------------------------------------------------|
| **ArrayList**     | Когда нужен **быстрый доступ по индексу** и вставка в конец.      |
| **LinkedList**    | Когда важны **частые вставки и удаления в середине**.             |
| **HashSet**       | Когда важны **уникальность элементов и высокая скорость `O(1)`**. |
| **LinkedHashSet** | Когда нужна **уникальность + порядок вставки**.                   |
| **TreeSet**       | Когда важна **сортировка элементов**.                             |
| **HashMap**       | Когда важен **быстрый доступ по ключу `O(1)`**.                   |
| **LinkedHashMap** | Когда нужен **порядок вставки + быстрый поиск**.                  |
