## Apache Airflow

**Apache Airflow** — это open-source инструмент, который позволяет разрабатывать, планировать и осуществлять мониторинг
сложных рабочих процессов. Он используется для автоматизации задач и оркестрации рабочих процессов. В Airflow описание
процессов происходит с использованием языка программирования Python, что дает высокую гибкость и мощные возможности для
создания кастомизированных процессов.

### Основные возможности:

1. **Оркестрация задач**: Airflow позволяет организовывать различные задачи и выполнять их по расписанию или в
   зависимости от других задач, создавая сложные конвейеры (DAGs).
2. **Планирование задач**: Airflow позволяет запускать задачи с определенной периодичностью или при наступлении заданных
   условий (например, после выполнения предыдущей задачи).
3. **Мониторинг**: Airflow предоставляет web-интерфейс, в котором можно отслеживать статус выполнения задач, а также
   ошибку или причину их неудачного завершения.

### Примеры использования:

- **ETL-процессы**: Извлечение данных из разных источников, их трансформация и загрузка в хранилища данных (Data
  Warehouses). Например, можно настроить задачи на регулярное извлечение данных из API, выполнение очистки данных с
  использованием Spark, а затем загрузку их в базы данных.
- **Обучение модели машинного обучения**: Автоматизация тренировки модели с использованием заданных параметров, а также
  оценка и сохранение результатов.
- **Автоматизированные отчеты**: Создание отчетов по данным из разных источников, автоматическая генерация и отправка их
  на почту.
- **Мониторинг и уведомления**: Организация процессов, которые следят за состоянием серверов или приложений, и
  уведомляют администратора о любых сбоях или ошибках.

### Основные компоненты и концепции:

#### **DAG (Directed Acyclic Graph)**

- Это основной строительный блок Airflow, который представляет собой граф, состоящий из задач, которые нужно выполнить в
  определенном порядке. DAG описывает структуру и порядок выполнения задач, их зависимости и расписание.
- **Пример DAG**:
  ```
  from airflow import DAG
  from airflow.operators.dummy_operator import DummyOperator
  from airflow.operators.python_operator import PythonOperator
  from datetime import datetime

  def print_hello():
      print("Hello Airflow!")

  dag = DAG('hello_airflow', start_date=datetime(2023, 1, 1), schedule_interval='@daily')

  start_task = DummyOperator(task_id='start', dag=dag)
  hello_task = PythonOperator(task_id='hello', python_callable=print_hello, dag=dag)

  start_task >> hello_task
  ```

#### **Operators**

- Это базовые строительные блоки, которые описывают, что будет происходить во время исполнения задачи. Например:
    - **BashOperator**: выполняет команду в Bash.
    - **PythonOperator**: запускает Python-функцию.
    - **EmailOperator**: отправляет email-сообщение.
    - **SQLOperator**: выполняет SQL-запрос в базе данных.
    - **HttpSensor**: ожидает ответа от API.

#### **Scheduler**

- Airflow использует **Celery**, который управляет выполнением задач, распределяя их между воркерами. Планировщик (
  Scheduler) обрабатывает DAG'и и ставит задачи на выполнение в очередь. В зависимости от конфигурации задачи могут быть
  выполнены на разных машинах или контейнерах.

#### **Sensors**

- Это операторы, которые ждут выполнения определенного условия. Например, можно ожидать появления нового файла в папке
  или получения ответа от внешней системы.

#### **Executors**

- Airflow использует несколько типов исполнителей, которые отвечают за то, как и где выполняются задачи:
    - **SequentialExecutor**: выполняет задачи по одной.
    - **LocalExecutor**: выполняет задачи на локальной машине параллельно.
    - **CeleryExecutor**: распределяет задачи по кластеру с помощью Celery и брокера сообщений (например, Redis).
    - **KubernetesExecutor**: запускает задачи в контейнерах Kubernetes.

#### **Task Dependencies**

- Задачи могут зависеть от других задач, то есть одна задача не начнется, пока не завершится другая. В Airflow эти
  зависимости можно задавать через операторы `>>` или `<<` (например, `task1 >> task2` означает, что `task2` будет
  выполняться после `task1`).

### Пример простого DAG

Допустим, у нас есть следующий сценарий:

1. Извлечь данные из источника.
2. Преобразовать данные.
3. Загрузить данные в базу данных.

Пример кода для описания такого DAG:

```
from airflow import DAG
from airflow.operators.python_operator import PythonOperator
from datetime import datetime


def extract_data():
    print("Extracting data")


def transform_data():
    print("Transforming data")


def load_data():
    print("Loading data into database")


dag = DAG('etl_process', start_date=datetime(2023, 1, 1), schedule_interval='@daily')

extract_task = PythonOperator(task_id='extract', python_callable=extract_data, dag=dag)
transform_task = PythonOperator(task_id='transform', python_callable=transform_data, dag=dag)
load_task = PythonOperator(task_id='load', python_callable=load_data, dag=dag)

extract_task >> transform_task >> load_task
```

### Резюме

Airflow — это мощный инструмент для автоматизации рабочих процессов. Он позволяет управлять сложными процессами с
помощью Python, интегрируя различные системы и обеспечивая мониторинг и управление ими. Удобный интерфейс и гибкость
делают его идеальным для таких задач, как ETL, машинное обучение, автоматизация отчетности и DevOps.
