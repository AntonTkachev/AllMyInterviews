# Эволюция схемы данных: управление изменениями в хранилищах

## 📌 Что такое Schema Evolution?

Эволюция схемы – это механизм, позволяющий изменять структуру данных **без потери совместимости**.  
Используется в **DWH, Data Lake, потоковой обработке (Kafka, Flink)** и API-системах.

## 🛠️ Где применяется?

| Формат данных   | Механизм версионирования                 |
|-----------------|------------------------------------------|
| **AVRO**        | Schema Registry, поддержка совместимости |
| **Parquet**     | Эволюция схемы через метаданные          |
| **ORC**         | Гибкое управление изменениями            |
| **Protobuf**    | Версионирование API через `.proto`       |
| **JSON Schema** | Валидация входящих данных                |

## 🔄 Виды совместимости

| Тип          | Описание                         |
|--------------|----------------------------------|
| **Backward** | Новая схема читает старые данные |
| **Forward**  | Старая схема читает новые данные |
| **Full**     | Поддержка и Backward, и Forward  |
| **None**     | Нет проверки совместимости       |

## ⚙️ Что делать при изменении схемы в S3?

1️⃣ **Добавление нового поля** – можно ничего не менять, если формат поддерживает Schema Evolution.  
2️⃣ **Удаление поля** – лучше не удалять физически, а оставить `NULL`.  
3️⃣ **Изменение типа данных** – требует миграции старых данных.  
4️⃣ **Изменение структуры (nested → flat)** – нужен ETL или версионирование данных (`s3://bucket/v2/`).

## 🚀 Лучшие практики

✅ Использовать **AVRO/Parquet/ORC** – они поддерживают Schema Evolution.  
✅ Хранить схемы в **Schema Registry** (Kafka, Confluent, AWS Glue).  
✅ Использовать **версии данных** (S3 `v1/`, `v2/`) при разрушающих изменениях.  
✅ **Версионировать API** с помощью Protobuf или JSON Schema.
