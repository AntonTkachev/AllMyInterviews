# **Terraform**

**Terraform** — инструмент декларативного управления инфраструктурой.

Если есть **10 серверов**, развернутых в **AWS**, и нужно развернуть ещё **5**, в **Terraform** это выглядит так:

```hcl
resource "aws_instance" "example" {
    count = 10 -> count = 15
    ami = "ami-0c55b159cbfafe1f0"
    instance_type = "t2.micro"
}
```

🔥 **Terraform добавит 5 новых серверов, а не создаст ещё 15 новых серверов. Такой подход и называется декларативным.**

---

## **Процесс работы с Terraform**

1. **Желаемое состояние инфраструктуры** описывается в **конфигурационном файле**.
2. Указывается **провайдер**, который будет исполнять работу.
3. Применяется **последовательность команд:**
    - `terraform init` — **инициализация провайдера**;
    - `terraform plan` — **валидация конфигурационного файла**;
    - `terraform apply` — **применение конфигурации**.

---

# **Terraform State**

**Terraform State** – это файл состояния, который хранит информацию о текущем состоянии инфраструктуры.

📌 **Почему Terraform использует State?**

- **Отслеживает разницу** между текущей инфраструктурой и кодом.
- **Избегает дублирования ресурсов** при повторных запусках `terraform apply`.
- **Ускоряет работу**, так как не запрашивает данные из облака при каждом запуске.

📌 **Где хранится Terraform State?**

- **Локально** (`terraform.tfstate`) – используется для тестов.
- **Удалённо** (S3, GCS, Terraform Cloud) – для командной работы.
- **DynamoDB** – для блокировки (`lock`) и предотвращения конфликтов.

# **Terragrunt**

– инструмент-надстройка над **Terraform**, упрощающий управление инфраструктурой и обеспечивающий удобную работу с
конфигурациями.

📌 **Зачем использовать Terragrunt?**

- **Повторное использование кода** – помогает избежать дублирования конфигураций.
- **Автоматическое управление backend’ом** – упрощает работу с `Terraform State`.
- **Модульность** – легко разделять инфраструктуру на независимые части.
- **Гибкость и параметризация** – возможность переиспользовать переменные и шаблоны.

📌 **Пример Terragrunt-конфигурации:**

```hcl
terraform {
  source = "git::ssh://git@github.com/company/repo.git//modules/ec2?ref=v1.0"
}

inputs = {
  instance_type = "t3.medium"
  region        = "us-east-1"
}
```
